1. 先校正项目定位

这是 Qt 5 Windows 客户端 + Linux C++ 服务端的教学/个人网盘。客户端使用 WinSock、Qt Widgets 和 SQLite；服务端使用 TCP、epoll、pthread 线程池、MySQL 与 Linux 文件系统。

不要称它为“生产级分布式网盘”。仓库没有完整首次建库脚本、自动化测试和匹配当前源码的运行验证；服务器文件仍落在单机硬编码目录。

层主要类职责
客户端界面LoginDialog、MainDialog采集操作、显示目录和传输状态
客户端控制CKernel协议封装、任务管理、SQLite、界面协调

服务端网络Block_Epoll_Net、thread_pool连接就绪、完整收包、任务排队和执行
服务端控制TcpKernel、CLogic协议路由、认证和文件业务
持久化CMysql、CSqlite、Linux FS元数据、任务缓存、文件本体

3. 一条请求如何往返

用户点击上传
→ MainDialog 发出 SIG_uploadFile
→ CKernel 计算元数据并封装 STRU_UPLOAD_FILE_RQ
→ TcpClient 加 4 字节包长并发送
→ Block_Epoll_Net 收到完整帧并投递线程池
→ TcpKernel 按协议号路由到 CLogic::UploadFileRq
→ CLogic 操作 MySQL / 文件系统并返回响应
→ 客户端协议映射找到响应处理函数
→ CKernel 更新任务，MainDialog 更新界面

4. 90秒口述模板

“这是一个 C/S 架构的个人网盘。Windows 客户端用 Qt 5 和 WinSock，Linux 服务端用 C++、epoll 和动态线程池，MySQL 保存用户与文件元数据，Linux 文件系统保存文件内容，客户端 SQLite 保存未完成传输任务。系统支持注册登录、文件/文件夹上传下载、MD5 秒传、分享、删除和断点续传。TCP 上层采用包长帧解决消息边界，文件按 64 KiB 分块并逐块确认。项目重点是网络消息处理、并发任务调度、文件去重和跨数据库/文件系统一致性；当前仍属于教学实现，身份绑定、协议可移植性和资源回收需要继续完善。”
