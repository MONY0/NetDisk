Lesson 02 · 9 minutes

从 main 到第一次目录刷新

目标：把客户端启动、登录和事件传递说成一条连续调用链，而不是罗列类名。

Qt事件循环观察者跨线程

1. 启动顺序

  1. QApplication 创建 Qt 应用并准备事件循环。
  2. CKernel::GetInstance() 构造唯一客户端业务核心。
  3. 加载 config.ini，默认 IP 为源码中的地址、端口为8000。
  4. 创建下载根目录 应用目录/NetDisk。
  5. 创建 TcpClientMediator 并连接 SIG_ReadyData。
  6. 主动连接服务端，创建登录和主窗口。
  7. 建立 UI → CKernel 与 CKernel → UI 的信号槽关系。
  8. a.exec() 开始 Qt 事件循环。

2. 登录成功后的闭环

LoginDialog 收集手机号和密码
→ SIG_LoginCommit
→ CKernel::slot_loginCommit
→ 密码拼接固定 KEY 后计算 MD5
→ 发送 STRU_LOGIN_RQ
→ 服务端查 t_user 并返回 userid/name
→ CKernel::slot_dealLoginRs
→ 隐藏登录窗，显示主窗口
→ 为 userid 打开 SQLite 数据库
→ restoreCachedTasks()
→ 请求根目录文件列表和我的分享

客户端本地缓存不是全局一个数据库，而是按用户 ID 使用 database/<userid>.db，避免不同账号的任务混在一起。

3. 为什么使用 signal/slot

这里最重要的不是“Qt有信号槽”，而是两种解耦：

  • 界面与业务解耦：MainDialog只表达“用户要上传”，不负责组包和发送。
  • 网络线程与GUI线程解耦：接收线程发出数据到达事件，槽函数由Qt事件系统调度；GUI控件不应在WinSock接收线程直接修改。

当前信号携带 char*。队列连接只复制指针值，不管理缓冲区所有权。代码依赖“网络层分配、CKernel处理后delete[]”的人工约定；更稳妥的参数是 QByteArray 或拥有明确所有权的消息对象。

4. CKernel是什么角色

它既是应用控制器，又有外观模式作用：UI只面对登录、上传、下载等业务槽，不直接接触Socket、协议结构和SQLite。但它同时承担过多职责，不能称为严格MVC。

可以说不要说
CKernel是客户端业务中枢和应用控制器项目严格实现了MVC
Qt信号槽体现观察者模式所有回调都自动线程安全
队列连接可跨线程投递事件裸指针参数会自动深拷贝

5. 面试口述

“客户端启动时先构造 QApplication，再通过局部静态单例创建 CKernel。CKernel加载网络配置和系统路径，创建TCP适配层、登录窗口和主窗口，并建立信号槽。登录成功后根据userid打开独立SQLite缓存，恢复未完成任务，再请求根目录和分享列表。UI层只发业务事件，协议封装、文件任务和网络交互集中在CKernel。网络接收发生在独立线程，数据通过Qt信号投递回业务/UI线程。”

6. 检索练习

问题：为什么登录成功后才初始化SQLite，而不是程序启动就初始化？

数据库文件按用户ID命名。登录前还不知道用户身份；登录后初始化可以隔离不同账号的传输任务。更生产化的实现还要防止客户端伪造userid，并处理切换账号时旧任务与连接的清理。
